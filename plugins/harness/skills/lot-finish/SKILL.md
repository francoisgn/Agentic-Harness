# Finish a lot

Issues of the lot: $ARGUMENTS (otherwise those claimed on the current branch).
References: `.harness/docs/CONVENTIONS.md` (PR, comments), `.harness/docs/ORCHESTRATION.md` §3 (adversarial
review), `.harness/docs/CI-BUDGET.md` (otherwise the same files under `${CLAUDE_PLUGIN_ROOT}/docs/`).

1. **Local checks**: tests, lint, coverage, the project's local CI script (`CLAUDE.md` › Build and tests).
   `git status`: no tracked file forgotten, no artefact. Each new test has been seen **failing** without the
   change. App code that cannot be compiled here (Linux cloud): reread with compiler-level rigour, and noted.
2. **Self-review**: skill `/lessons-check` (or by hand against `LESSONS.md`). Docs, plan, regulation updated in the
   same commits; **README**: `/readme-update` (the lot's row in the progress table, badges, architecture diagram if
   the modules or flows changed; `.harness/docs/README-STANDARD.md`). Version and What's New **not** touched (handled
   at integration).
3. **Adversarial review**: a fresh subagent, **of another model** than the author, read-only, receives only the diff
   (`git diff origin/<integration>...HEAD`), the spec, `ESSENTIALS.md`, `LESSONS.md`, with the instruction from
   ORCHESTRATION.md §3. Never your conclusions. Fix each High/Medium finding in one commit, have it rechecked.
4. **Commits**: atomic per issue, in the project's language, `git log` style, session attribution at the end of the
   message.
5. **A single push**, then a **draft** PR to the integration branch. Body: `Closes #n` one line per issue; summary
   per issue; verification; watch points / not tested; `## Changelog` (user side, or "None"); author / reviewer
   models; generation line. Title in the style of previous PRs.
6. **Closing comments** on each issue: done, PR link, what is left, decisions made (simplest option chosen when
   ambiguous), to validate on the device; footer `---` / `_Generated by [Claude Code](https://claude.ai/code)_`.
   Update the PR column of the umbrella issue's table; close it if all its points are closed.
7. **Discovered work**: one labelled issue per subject (never only a note).
8. Do not move to "Ready for review" or merge without the operator's approval, unless the project's policy says
   otherwise. Report: PR link, what is left, what must be checked on the Mac (`/review-round` for what follows).
