# Start a lot

Target issues: $ARGUMENTS

Reference rules: `.harness/docs/METHODOLOGY.md` §2 (otherwise `${CLAUDE_PLUGIN_ROOT}/docs/METHODOLOGY.md`) and the
project's `CLAUDE.md`, which takes precedence.

1. **Real state first**: `git fetch origin`, read the integration branch (`.harness/config.json` →
   `integration_branch`, otherwise `CLAUDE.md`). Read each issue **and all its comments** (GitHub tool).
2. **Ready?** For each issue, stop and say so if:
   - it is already claimed by another session ("Claimed" comment, label `status: claimed`);
   - it carries `status: needs-decision` or `status: blocked`, or a dependency (`Depends on`, lot plan) is not
     closed;
   - it carries `needs: host` and the session runs in the cloud (`CLAUDE_CODE_REMOTE=true`);
   - an axis label is missing (type, priority, difficulty, status): propose it rather than guess;
   - its inputs do not exist (data, screenshots, regulatory sources, access).
   Compare the `difficulty:` label with the session's model tier: more demanding → tell the operator before
   starting.
3. **Duplicates and overlaps**: search issues and PRs (open and closed) on the same subject, and open PRs that
   touch the same files.
4. **Claim**: on each issue, a comment:
   ```
   Claimed: branch `claude/<lot>`
   Agent: <project>.<orchestrator|solo>.lot.<target> (<model>)
   - <plan in 3 to 5 bullets: what, where, how it is tested>

   ---
   _Generated by [Claude Code](https://claude.ai/code)_
   ```
   (and replace its `status:` label with `status: claimed`).
5. **Branch**: `git switch -c claude/<lot> origin/<integration>` (or a worktree if other lots run in parallel:
   `git worktree add ../<project>-<lot> -b claude/<lot> origin/<integration>`).
6. **Spec**: a lot has its spec `docs/lots/LOT-XXX-*.md` (template `docs/lots/TEMPLATE.md`); a bug or a task relies
   on the issue. Note the lessons in `LESSONS.md` that apply (project scope) and keep them in mind.
7. Agent identifier (`.harness/docs/ORCHESTRATION.md` §7): the one given by the orchestrator, otherwise
   `<project>.solo.lot.<target>`; reuse it in the commits (`Agent:` trailer) and the PR.
8. Report in 5 lines: issues claimed, branch, plan, risks, what will have to be validated on the Mac.
